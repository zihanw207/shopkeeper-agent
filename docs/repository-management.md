# 仓库与敏感信息管理

此仓库最初以私有可见性创建。公开前应再次核对内容，尤其是自行添加的截图、实验记录和数据。私有可见性不能代替密钥隔离。

## 凭据放在哪里

- `.env`：API Key 和数据库密码，只保留在本地。
- `conf/app_config.yaml`：实际配置，只保留在本地；敏感字段通过环境变量读取。
- `.env.example` 和 `conf/app_config.example.yaml`：可上传的空值 / 环境变量模板。
- `logs/`、`app/agent/logs/`、`data/` 内的会话数据库、`evals/reports/`：运行产生的日志和结果，不进入版本控制。
- `.local-backups/`：本地配置备份，不上传。

本次配置迁移保留了本机实际凭据，文件权限设为仅当前用户读写。迁移前的配置副本留在 `.local-backups/github-setup/`，不进入仓库。请勿将环境文件或这些备份粘贴到 Issue、截图或公开聊天中。

原 Docker 配置和历史提交存在明文数据库密码，因此新仓库使用独立的初始提交。原有历史仍保存在本地分支；**不要使用 `git push --all` 或 `git push --mirror` 将旧分支一并上传**。正常使用当前开发分支的 `git push` 即可。

如果某个真实密钥曾经被公开，删除文件或改成私有仓库不能撤销泄露，需要在服务提供方撤销并重新生成。本次未发现本地 LLM API Key 出现在拟发布文件或待推送提交中；这不替代对其他历史分享渠道的检查。

## 日常提交

先安装项目提供的提交钩子：

```bash
uv run pre-commit install
```

Gitleaks 在提交时扫描变更，除了默认规则，也会检查低复杂度数据库密码和环境文件中的凭据；格式检查随后运行。不要通过关闭钩子来绕过密钥告警。

按功能选择文件提交，避免把临时文件整批加入：

```bash
git status --short
git add app/agent/sql_policy.py tests/test_sql_policy.py
git diff --cached --stat
git commit -m "fix: support safe EXISTS subqueries"
git push
```

`.gitignore` 只能自动忽略尚未跟踪的文件。若之后误把环境文件加入暂存区，应先撤销暂存并检查；不要仅添加忽略规则就假定内容已安全。当前真实配置已从新仓库的跟踪范围中移除。

GitHub Actions 使用占位配置执行离线测试，不需要配置真实模型 Key。真实模型评测在受控的本地环境显式运行；原始报告保持本地，发布结论时只提取经审查的统计结果。

## 有意义的版本记录

每次提交说明具体问题和修改结果，例如“保留多轮追问的地区筛选”“修复 EXISTS 被误拦截”，而不是只写“更新”。一次实验记录固定代码、数据、模型、提示词版本与评测标准，失败题修复后作为回归题保存。
