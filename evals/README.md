本目录配合开源教学项目的第一阶段二次开发。12 道种子题用于调试和后续扩展，不是保留测试集。当前没有已测得的模型准确率提升。

已新增 [独立测试集 v1](holdout/v1/README.md)：46 个场景、63 轮输入，覆盖复杂查数、澄清拒绝、证据分析和多轮状态。57 条参考查询、18 条可执行错误变体均通过 SQLite / MySQL 核对；尚未运行真实模型。该集使用独立采集器、按语义列匹配及人工复核规则，不沿用下文早期种子集的按列位置比较方式。

## 本轮已实现

- SQL 校验失败后最多修正两次，每次必须重新校验；执行阶段可修正的 SQL 错误使用相同预算。
- 解析模型 SQL，限制为单条 SELECT/UNION、配置内的数据表及明确开放的函数；拦截写入、跨库、锁、变量、递归查询和自定义执行提示。
- 真正发往数据库的是检查后重新生成的 SQL。只通过 EXPLAIN 的字符串才能进入图中的执行节点；仓储执行入口仍重复做策略检查。
- 默认结果上限 200 行；MySQL SELECT 时限 10 秒，客户端数据库等待上限 11 秒；问数流程预算 120 秒。限制减少资源滥用，不能证明所有查询都很便宜。
- 模型筛选表字段后保留所选表的主外键，并避免原地修改输入状态。尚未实现自动补齐未召回的中间关联表。
- SSE 结果新增实际 SQL、行数上限和修正次数；失败事件提供错误分类；HTTP 响应带 `X-Request-ID`。

应用层检查不替代只读数据库账号、字段/行权限和访问认证。当前数据库账号权限没有调整，函数允许列表偏保守；合法但未支持的查询可能被拒绝。

## 运行

在项目根目录执行。依赖新增 SQLGlot 和显式声明的 HTTPX；本机环境已经安装，换环境先运行 `uv sync`。

```bash
# 不调用模型的单元与图分支测试
uv run python -m unittest discover -s tests -v

# 从仓库自带种子数据构建内存 SQLite，核对参考 SQL
uv run python -m app.scripts.evaluate_agent --check-fixture

# 只对本机 MySQL 执行固定的参考 EXPLAIN/SELECT，不调用模型
uv run python -m app.scripts.evaluate_agent --check-database
```

完整在线评测需要先启动 Docker 服务及后端。它会调用项目配置的模型 API，发送用户问题及问数所需的 Schema、指标和检索上下文，并产生模型使用费用。

```bash
uv run fastapi dev main.py
```

在另一终端运行：

```bash
# 小规模链路验证
uv run python -m app.scripts.evaluate_agent --limit 3 --tag sql-loop-v1-smoke --output evals/reports/smoke.json

# 全部种子题
uv run python -m app.scripts.evaluate_agent --tag sql-loop-v1 --output evals/reports/sql-loop-v1.json
```

报告保存在本地 `evals/reports/`，已加入忽略规则，因为报告可能包含实际查询结果。

## 比较规则与报告

- 先在当前 MySQL 上执行每题的固定参考 SQL，再调用真实 `/api/query`，比较结果。评测期间请保持数据库数据不变。
- 多列题明确要求列顺序；比较时忽略列别名，但保留列位置。模型返回了另一列顺序会判失败，不应把这个结果直接解释成业务计算错。
- 无排序要求时忽略行顺序，但保留重复行的次数；有排序要求时严格比较行顺序。
- 数值绝对误差允许 0.01；NULL 不等于 0 或空字符串。其他类型按值比较。
- 空参考集合单独列出，不计入主执行正确率。对于缺数据导致的 NULL 聚合、非唯一 Top-K 边界等情况，扩展数据集时还需要增加专门检查。
- 保存题目级结果、错误类别、修正次数、首事件耗时、总耗时、p50/p95、非空结果正确率、首次成功率和修复后的正确率。
- 保存模型名称、Git commit、工作区是否有改动、源代码/提示词/数据集/参考结果摘要。模型名来自本地配置；如果评测远端服务，应确认服务使用同一配置。
- token 和成本暂为 null，不能当成零成本。未接入完整 LLM Trace，也尚未测量各节点耗时。
- 参考 SQL 通过一次数据库验证只代表能执行，业务定义仍需人工审阅。SQLite 检查仅适用于这套简单种子查询，不能代替 MySQL 方言测试。

## 后续实验

当前种子集作为开发集，新建的 holdout/v1 在首次模型评测前已冻结；与开发题共享数据，需分开报告背景数据新题和已知边界上的组合题。建议对照：完整 Schema 基线、当前三路召回、融合召回、融合+重排。每次只改变一个因素，并报告失败案例；若用保留题调参，应另建最终测试集。

AOV 元数据口径仍是待修问题：现配置依赖 order_quantity，且有“平均单价”别名。本集 AOV 题显式固定平均订单金额定义；它不能替代修正业务配置和重新同步索引。重复构建元数据的幂等性也应先补齐，避免直接重跑旧脚本造成主键冲突。
